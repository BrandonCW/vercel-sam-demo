Stage 1: The Mocked & Simulated Foundation

The prototype MVP established the Split Workbench UI and Next.js shell, but all AI evaluation and deep reasoning were heavily simulated. Jev MEDDPICC scores were generated by regular expression keyword matchers, System 2 used ~550 lines of hardcoded scenario pipelines, and database failures were silently swallowed into in-memory dictionaries.

Real AI Evaluation 0% (Pure Heuristics)
Persistence Model In-Memory + Postgres Catch

Data Flow & Architectural Topology

What Changed & Architectural Setup

  • Scaffolded initial Next.js App Router project and Split Workbench layout.
  • System 1 "Jev" was simulated with regex pattern searches against AE/SA notes.
  • System 2 was a static ~550-line pipeline returning predetermined JSON forms.
  • Persistence caught DB errors and silently defaulted to in-memory maps.

Benefits & Limitations

  • Pro: Zero API key dependency; enabled UI layout and UX testing offline.
  • Pro: Defined canonical MEDDPICC rubric weights and stage gate bounds.
  • Con: Completely dishonest demos; zero actual model intelligence.
  • Con: Silent failure masking hid misconfigured environment variables.

State Persistence Deep Dive

  • Schema defined for Postgres (Neon), but wrapped in catch-and-continue logic.
  • When POSTGRES_URL failed, state quietly resided in an ephemeral dictionary.
  • Session state was represented as raw string flags passed over HTTP endpoints.

Stage 3: Eve Agent Orchestration & `useEveAgent`

Shifted deal qualification from stateless Next.js routes into native Eve Agent architecture. A single Assessment Session persisted durably over 30 days, idling at zero cost while waiting for the Solutions Architect. The web UI adopted useEveAgent over same-origin /eve/v1, retiring redundant server bridges. Subagents were flattened into direct root tools with progressive streaming.

What Changed & Architectural Setup

State Persistence Deep Dive

Stage 4: Unified Eve Workflow Tool & Code Verdict (PR #2)

PR #2 consolidated the multi-turn LLM reasoning into a single, deterministic defineWorkflowTool named run_assessment. Step sequence is guaranteed in code (Jev ➔ System 2 ➔ ctx.ask pause ➔ SA feedback ➔ rescore ➔ writeback). Pass/fail is determined deterministically in code via AssessmentResult. Root LLM role is reduced to a single call, enabling Gemini 3.8 Flash and slashing costs by 97%.

Data Flow & Architectural Topology

What Changed & Architectural Setup

  • Replaced multi-step LLM reasoning with a single defineWorkflowTool.
  • Steps sequenced deterministically in code via "use step" functions.
  • Parked human-in-the-loop state using native ctx.ask.
  • Completely removed fragile LLM turn schema outputs (TurnOutcomeSchema).

Benefits & Key Metrics

  • 97% Root Cost Reduction: Dropped from $0.10 to $0.0025 per Acme run.
  • Zero Step Hallucination: Models cannot misorder, loop, or skip steps.
  • Fast Cycle Times: Turn 1 reaches pause in 36.3s; feedback turn takes 3.9s.
  • Flawless Eval Pass: 28/28 Acme, 15/15 Globex, 15/15 Soylent live checks.

Dual-Layer State Model

  • Eve Workflow Engine: Caches step execution results & pauses on ctx.ask.
  • Postgres (Neon): Authoritative CRM store for Opportunity, SA notes, & audit rows.
  • Atomic SQL transactions with advisory locks prevent race conditions on feedback.
